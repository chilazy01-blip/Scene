# 同 G1 原生任务栈：来源核对与方法结论

本轮找到了值得继续复用研究的完整取放实现，不能再概括为“开源项目只有 WBC、没有完整任务”。其中最有价值的是 `supat-roong/g1-manipulation-challenge` 的 IK 任务管线。但**本轮尚无来源同时通过原生运行合同、现有机器人执行条件、物理质量及整包资源准入**；没有进行新的物理试次，没有生成合格轨迹。按已批准方案的来源/质量/资源退出条件，六小时采集目标提前收束，`objective_achieved=false`。这不是一次新的动态失败，也不是资源已经用尽。

## 本轮怎样借鉴其他工作

先读完整任务调用链，找出别人的成功依赖哪些技能和条件；能保真接入的组件直接复用，需要迁移的部分明确为适配；把源任务先作为参照，再接入自己的生成器。机器人、手型、全身动态任务和数据质量目标继续保留。

重点借鉴三个方面：

1. **任务组织。** 从机器人实测停靠位置选择抓取站位和手姿；把抓取、负载搬运、放置与松手作为有明确交接条件的技能。旧方法已有反馈、负载门和几何修订，问题不能简化成“完全没有闭环”；当前缺的是这些部分组成完整任务后的可靠动态证据。
2. **成熟组件和适用范围。** 冻结已有步行能力，在其上复用对象相关的任务控制；根据手与物体几何选接近路径，并考虑抓住之后能否稳定搬运、最后能否释放。对象相对坐标和重新选择站位，是接自有场景的重要接口。
3. **验证方式。** 先确认上游成功可复现，再判断适配是否保留能力；独立检查接触、完整搬运和放置质量。公开成功率、视频、源码静态检查与本地动态验收分别报告。

这些结论支持调整验证顺序与控制层次；它们尚未证明哪一种外部抓持参数能够修好我们的历史失败。

## 为什么不能在本轮直接开跑

**最接近的候选确实是同一机器人/手型家族。** 静态逐项对照显示，supat-roong 与当前模型的 43 个关节全部有名称映射，43 个数值活动范围全部一致。但六个腕关节的力矩限值不同，手指 PD 增益/阻尼和被动关节参数不同；源任务使用的底层策略接口也不同。位置执行器与力矩执行器在合适控制下可以对应，不能仅凭 XML 标签不同就说换了机器人；同样不能只改关节名字便宣称动态等价。需要显式映射、限幅与实测验证，现有成功记录没有覆盖该适配。

**预设的 40 秒单次上限没有依据候选完整任务时长制定，这是本轮计划本身的缺口。** supat-roong 保存的六条成功回归记录为 101.64–206.90 秒仿真，全部超过该上限。原任务默认上限为 300 秒。不能把真实任务加速、截短或换个场景后仍叫作忠实复现；这些改变需要重新验证。也不能据此断言任何适配后的任务都必须超过 40 秒。下载体积和 CPU 路径目前并非这一路线的主要障碍。

**物理质量不能由上游通过的谓词代替。** 两个挑战分支的物体按 XML 计算约 8.90 g，滑动摩擦系数为 3；已读文件没有给出这组材料参数以及本项目力/瞬态门的标定依据。这并不证明参数一定不真实，但不足以通过已冻结的质量要求。supat-roong 的末态检查包含直立与两秒静止，却未在该成功谓词中完整证明独立承重、全底面/质心余量和全部本地接触门；Nu11ified 的短时间放置谓词同样不能替代。

Lucky Robots 及所查分支的完整公开树中没有发现 LICENSE 文件。源码可供本次审阅，后续代码/权重实际复用和分发的许可范围尚未核清；本轮未将其导入生产代码。这里记录来源状态，不把文件缺失扩大成作者一定禁止使用的结论。

## 可执行的后继方向

优先保留 supat-roong 为参照，下一里程碑应先按其真实时长核算**原生完整复现与当前执行条件迁移**，再估算跨生成布局的数据包。对齐同一套动态合同后，才有意义比较任务组织、接触技能和环境适配各自贡献。不要继续把六条数据产出建立在“原生栈拿来便能在 40 秒内通过本地质量”的假设上。

这项建议不自动启动新实验、扩大限额或降低原目标；本轮未形成可执行 ADMISSION。旧 B1/D7/WBC-goal/v2/v3/v4 和旧保留测试均继续关闭。

## 证据与记账

运行目录为 `payload_data_20261009/native_reuse_6h_20261011`。`reports/CHALLENGE_CONTRACT_COMPARISON.json` 保存 43 关节逐项对照、时长、物体计算和谓词差异；`reports/HMG_LOCAL_SOURCE_INVENTORY.json` 保存 80 个本地源码/配置对上游 blob 的核对，零不一致；`reports/SOURCE_DOWNLOAD_MANIFEST.json` 保存下载地址、HTTP 状态、固定版本和 SHA。实际消耗、退出原因及验证见 `CLOSURE.json`、`RUN_LEDGER.json`、`COUNTERS.json`、`CLOSURE_VERIFICATION.json`。

本轮物理任务/积分、策略前向、渲染、训练全部为零。网络限制导致的初次下载失败、一个请求路径拼写错误、一个来源入口 404 均已留证并计入实际记账；其中前两项已经分别通过授权网络读取与相对路径启动解决。源码审阅和工程纠错不能计作任务成功。

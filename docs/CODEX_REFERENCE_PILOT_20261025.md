# Codex 辅助任务参考：首轮接口与对照验证

2026-10-25，按用户“按照这个路线去做尝试”的指令，建立一个小规模开发试验：让 Codex 提出有界的动作参考方案，由确定性程序编译，继续使用原 SONIC29、手部原生 PD 和真实仿真验收。**当前接口已实现并完成本地验证；独立 Codex 调用尚未获准发送上下文，辅助组尚未运行，不能声称已证明轨迹改善。**

实验根目录：`/data/wsj/main/scene_runs/codex_trellis_v2/embodied_codex_reference_20261025_v1`。

## 本轮范围与固定条件

生产瓶颈是现有专家的动作参考依赖案例参数和人工修正。首轮先验证一个受限、可审计的提案接口及真实比较流程，不一次替换整个专家。

在看到新轨迹结果前，固定两个放置目标：原目标 Y 方向分别偏移 -30 mm、+30 mm。两组都复用原 `trial_07` 放置前的 1597 个控制周期、6428 个已计费物理步；这是一个原生场景内、共享抓取及持杯行走前缀的局部目标适配试验，不能当作两个独立场景或独立成功率样本。

模型只允许提出：

- 放置路径时长，65–110 个 50 Hz 控制周期；
- 收手路径时长，40–100 个控制周期；
- 与已提供证据对应的理由和时间成本权衡。

编译器保留上一段期望路径的起点、原放置/收手终点和抓取参考朝向。原几何、杯质量 150 g、摩擦、原生 PD、电机能力、关节限位、43 路控制、SONIC29 所有权、释放逻辑、阶段超时和原八项最终门保持。沿用 NoSlip0→3、3960 物理步激活的明确数值条件。正例另外要求最终杯身直立余弦至少 0.98，该质量条件在新案例物理运行前写入计划。

本轮声明两小时、新增物理积分最多 52000 步，包括任何成功后的原初始化全段复验；单进程 16 GiB、前 8 个可用 CPU 核、BLAS 单线程。四组最坏后缀与成功复验总预留为 45008 步。授权来自本次新指令，没有沿用已收束的旧六小时窗口。

## 已完成的实现与检查

源码位于 `sage/experiments/embodied_codex_reference_v1/`：

- `proposal.py`：实际 `codex exec` 调用、结构化输出、时限、请求/响应与事件留档；没有伪造方案回退。
- `task.py`：把合法提案编译为连续参考，其他阶段和控制逻辑继承原成功专家。
- `protocol.py`：新授权、冻结依赖检查和带文件锁的成本账，预留成功复验成本。
- `prepare_bound.py`：冻结相同的两组目标、真实前缀与方案身份。
- `job.py`、`review.py`：执行、独立审计、受力、视频、质量检查和成本测量。

执行器、独立审计、复验和渲染基于冻结版本另建文件，转换记录在 `RUNNER_PROVENANCE.json`。没有改动历史成功实现、模型、报告和已有生成器修改。

12 项定向检查全部通过：非法字段、越界值、布尔值冒充整数和虚构证据被拒绝；路径起点及终点连续性、物理状态不写入、原阶段判断和站立交接继承得到检查。正式依据为 `CONTRACT_TESTS.xml`。

启动前的元数据序列化错误已查因：原项目 `read_bound_json` 要求内嵌内容哈希，新建授权/计划最初用了普通 JSON。预检以零物理步拒绝；原失败文件保留，新建 `AUTHORIZATION_BOUND.json`、`PLAN_BOUND.json` 和 `baseline_v2`，用项目原有 `safe_save` 正确序列化。两个新版本都通过了真实前缀的零积分精确恢复。

额外包围盒检查也保持诊断地位：杯包围盒完全位于桌内的条件会拒绝已认证的原目标；名义目标高度下，原目标和新目标静态均未接触桌面。不能把这些未经校准的静态条件临时变成新的动态硬门。结果保留在 `TARGET_GEOMETRY_DIAGNOSTIC.json`，两个预定目标未更换。

## 失败证据与解释范围

`PLACEMENT_CAUSAL_COMPARISON.json` 对比原成功轨迹和两个新目标：

- 原成功轨迹进入释放时杯身直立余弦约 0.97635，最终约 0.99978；
- 两个新目标进入释放时分别约 0.93104、0.88309，在释放阶段进一步侧倒；
- 原放置阶段检查手腕到达、桌面支撑和 XY 误差，没有杯身姿态条件。

这是实际时序与代码条件的证据，支持继续分析释放时的姿态和支撑交接。它没有证明“时长”是唯一原因，也没有证明增加一个直立门限就能恢复成功。`RELEASE_SUPPORT_DIAGNOSIS.json` 还保留反例：原成功轨迹在部分释放瞬间，质心投影也在当前桌面接触凸包之外，随后重新接触并恢复直立。因此不能用单帧静态支撑指标解释全部结果。

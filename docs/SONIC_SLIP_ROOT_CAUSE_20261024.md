# 原生白杯滑脱：已定位的共同失效机制与原项目差异

本轮查清了已经进入持杯走步的 7 条分支的共同直接失效机制：**拇指压在杯口上沿，余量约 1.2 毫米；承重期间持续缓慢滑移，拇指接触逐渐移出杯口边缘，首先丢失承重，随后其余手指失去对向支撑。** 这组初始抓姿没有被此前的握力、步态、反馈速度修改改变。

本轮仅重建历史状态、比较同一状态的接触求解及分析源码，新增物理积分 **0**，累计仍 **66,204 / 75,000**。未修改原任务、原模型或原控制器，未证明修正后的完整任务成功。

证据目录：`/data/wsj/main/scene_runs/codex_trellis_v2/embodied_native_sonic_slip_cause_20261024_v1`。

## 1. 抓取落点与最终失效

原白杯在杯体坐标系中的最高边缘为 z=55.00mm。分支 28 的实际承重接触点重建如下，使用原始杯子网格和记录中的杯体姿态，没有调整物理状态。

| 时刻 | 状态 | 拇指承重接触中心 z | 距最高边缘的轴向差 | 拇指接触法向沿杯轴分量 |
|---|---|---:|---:|---:|
| tick 1300 | 被判为悬停通过 | 53.760mm | 1.240mm | −0.396 |
| tick 1360 | 收臂末端 | 54.020mm | 0.980mm | −0.498 |
| tick 1430 | 持杯走步 | 54.559mm | 0.441mm | −0.592 |
| tick 1460 | 持杯走步 | 54.815mm | 0.185mm | 更靠近杯口上沿 |
| tick 1465 | 完全脱手前 | 55.034mm | −0.034mm | −0.751 |

这里的“余量”是接触中心距杯体最高边缘的轴向几何差，不是允许杯子整体移动的距离，也不是稳定性证书。接触有原设定的 1mm 厚度，所以接触点中心可略超出网格最高 z；这不代表网格或物体被改变。

到了 tick 1465，剩余 4 个拇指承重接触，其全部原生摩擦锥边界方向都只能沿杯轴向下施力，不能再沿杯轴向上托住杯子。按当时法向载荷计算，最有利的拇指轴向力仍为每单位法向力 −0.101。这来自真实接触法向、原 μ 和原金字塔摩擦锥的直接计算，不是将摩擦系数调低后的推测。

在实际记录时间 29.545s，拇指法向载荷首先归零，此时食指、中指仍分别有约 0.113N、0.153N；29.555s 三者全部归零。**拇指从杯口边缘失去支撑，是此次对向夹持崩溃的具体位置。**

![原始网格和真实接触点：左为悬停通过，右为脱手前](../../scene_runs/codex_trellis_v2/embodied_native_sonic_slip_cause_20261024_v1/RIM_CONTACTS.png)

机器证据：`RIM_CONTACT_EVIDENCE.json`，含接触坐标、摩擦锥方向、5ms 子步失效顺序及原始数据哈希。主 agent 已检查这张实际接触点图。

## 2. 为什么有摩擦、有夹紧力仍缓慢滑动

tick 1300，38 个法向力大于 0.01N 的接触中，有 32 个摩擦利用率小于 0.9，却全部仍存在大于 0.5mm/s 的切向相对滑速；接触滑速中位数约 1.63mm/s、最大约 4.73mm/s。持续滑移在走路之前已经存在，不能全部归因于走路突然甩动。

实际模型为 MuJoCo 3.7.0，运行 timestep=0.005s，Newton、pyramidal cone、impratio=1、noslip_iterations=0；原接触 solref=[0.02,1]、solimp 起始值 0.9。杯子仍为刚体；这里的“软”指接触约束的数值模型。MuJoCo 官方文档明确说明，这种接触模型即使没有用尽摩擦力，也会允许缓慢滑移。[MuJoCo 3.7.0：Softness and slip](https://mujoco.readthedocs.io/en/3.7.0/overview.html#softness-and-slip)。

为区分“求解精度不足”和“接触软化允许滑行”，对 12 个完全相同的历史 qpos/qvel/ctrl 状态做了零积分对照：

| tick 1300 的同一状态 | 载荷加权、沿当前滑动方向的相对加速度 |
|---|---:|
| 原求解条件 | −0.00216 m/s² |
| 仅将迭代上限100→200、容差1e−8→1e−12 | 完全相同 |
| 单独启用诊断 NoSlip 3 次后处理 | −0.22509 m/s² |
| 单独启用诊断 NoSlip 20 次后处理 | −0.25475 m/s² |

这表明原软接触的摩擦正则化确实影响制止滑移的响应；简单提高原求解收敛精度没有改变该状态。所有比较中的**当前速度和物理状态都相同**，没有把局部加速度或线性速度预测冒称为真实轨迹速度改善。NoSlip 是显式单列的诊断条件，未替换原案例，更没有据此宣称原任务成功。记录见 `RECORDED_STATE_MECHANISM.json`。

这 12 个状态的手指电机均未达到原 effort 上限；实际原生力矩正常产生，排除了这些状态下的电机力矩限幅失效。末段原生分配仍可能有控制空间、速率和动态跟踪问题，但它们不能解释“为什么未走路时已经发生软接触滑移”，也不能替代对杯口落点的检查。

## 3. 为什么我们一直把这组抓姿带入走步

当前手写控制器的 loaded_hover 判据允许相对位移至 15mm；接触质量要求瞬时静态承重余量≥1.25倍杯重、最大接触滑速小于 20mm/s，连续 50 个50Hz控制时刻通过便进入收臂。它没有检查接触点距杯口边缘的余量，也没有要求持续滑移收敛。

因此，**只有约1.2mm边缘余量、已持续滑动的抓姿，仍被标成 `loaded_hover_passed`。** 这是抓稳判定和抓取参考生成之间的具体缺口：短时有承重能力，并不保证接下来几秒接触点不会移出边缘。此处指出的是控制器进入搬运的诊断不足，原最终任务验收并没有被放宽，所有滑脱仍被最终门正确判失败。

本轮还对分支 21、22、24、25、26、27、28 做了交叉检查：它们 tick 1300 的全部力学复核记录完全相同，确实沿用同一组抓姿；每条分支最终都是拇指先失去承重，其他两指随后失去对向支持。

| 分支 | 最后一次有拇指承重的100ms抽样距杯顶差 | 最先失去承重的手指 |
|---|---:|---|
| 21 | 0.320mm | 拇指 |
| 22 | 0.053mm | 拇指 |
| 24 | −0.046mm | 拇指 |
| 25 | 0.172mm | 拇指 |
| 26 | −0.026mm | 拇指 |
| 27 | −0.040mm | 拇指 |
| 28 | −0.034mm | 拇指 |

证据：`BRANCH_CONTACT_COMPARISON.json`。这些是共用前缀的分支，不是七次独立采样的成功率统计。前面多次改变后续反馈或步态，却重复复用了同一组边缘抓姿；没有先定位拇指落点、接触迁移和假稳定放行，是此前排查顺序的不足。

## 4. 为什么原项目能展示成功，而接上 SONIC 后我们仍失败

原项目公开的自主操作示例通过上游 GR00T 任务策略驱动 SONIC；遥操作示例由操作者提供操作参考。SONIC 负责全身动作执行，不会凭接口连通自动生成当前杯子的可靠抓姿。[SONIC 项目页：VLA 与遥操作](https://nvlabs.github.io/GEAR-SONIC/)。

官方工作流是采集任务遥操作示范、微调任务策略、部署；动作同时包含64维身体token和左右各7维手部目标。[官方 VLA 工作流](https://nvlabs.github.io/GR00T-WholeBodyControl/tutorials/vla_workflow.html)。我们当前只运行原手写任务专家、真实 SONIC29 和原生 hands14，没有实际 GR00T 策略或在线重规划，不能把已经接通的数据接口等同于复现了原演示的任务策略。

**与本次失败直接相关的差距，是我们的任务专家选用了杯口边缘抓姿，并且把缓慢滑动的状态放行进入搬运。** 上游策略缺失是系统差异，不是证明“没有GR00T就必然失败”；成熟的专家规划和反馈同样可以作为当前训练数据生产的来源。原演示也不是在我们的白杯网格、刚体flex接触和完整验收条件下的对照，不能直接把其实机效果当作当前模拟条件已经校准。

## 5. 由证据决定的修正对象

首先应修改抓取参考生成，让对向手指落在杯身有足够接触余量的位置，并在原模型上核对接触随小幅相对运动的保持能力。随后给控制器增加搬运前的持续滑移与接触边缘余量检查，使尚在滑动的抓姿先调整而非直接进入走步。它们是控制逻辑修正，最终任务的原目标与成功标准保持。

原接触软化的数值校准可作为独立实验条件评估；若采用新的接触求解设置，必须明确单列，不能算作原冻结条件已经通过。当前零积分对照没有证明任何设置能完成整段任务，修正后的抓取—走步—放置—释放仍需新的有限物理测试窗口和完整审计。

本轮成果是已定位的共同失效机制及可复核证据，不是修复成功或合格样本。冻结的旧源码、结果和原始模型保持不变。

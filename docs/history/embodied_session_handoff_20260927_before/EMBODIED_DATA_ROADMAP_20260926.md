# 具身仿真数据项目长期路线与执行方式

2026-09-26。依据用户提出“要有长期计划，并解释为什么每次约半小时”，将后续工作从短诊断包串联为项目里程碑。本文件调整工作组织与路线优先级，不修改已封存实验结论、物理门或累计退出条件。

## 目标与当前位置

最终目标保持：自有场景生成器 → 可执行全身机器人任务 → 自动采集 → 质检和标准导出 → 下游学习验证 → 批量生产高质量训练数据。

面向未来自研的全身可移动机器人，首阶段仍采用参考本体，在家庭环境开展刚体取放，先做原地身体—单臂协同，再扩展物体和有限空间变化。夹爪A、多指手B分别评估；不把不同本体/控制器的差异全部归因末端。暂不把跨房导航、任意家务、软物体和硬件量产塞入首个数据闭环。

当前事实：

- 自有完整场景已接入A；原生控制、动作消费、接触诊断和失败记录有可复用实现。
- 当前Stretch夹爪开发线未获得完整取放成功。杯/瓶各累计3次，已关闭继续调参；A全部控制尝试累计11次115529步，不能全算抓取试验。
- B有一次无辅助站立通过（800步）、累计220低层前向、14原生手关节静态资格。非零手动作、上肢任务、家庭场景中的完整取放尚未验证。
- 当前这条全身任务链的合格训练episode为0，学习价值未验证。软件通过不替代这一缺口。

当前最重要的交付是选出一条能执行完整任务的参考采集方案，并让它真正产出可读取、可评价的数据。某个原生夹爪或控制器不是整个生成器项目必须无限修好的前置条件。

## 时间问题：短实验预算与项目工作时长分开

最近S1AB的三个worker分别约23.57秒（前置）、96.03秒（两次动态）、12.57秒（保存审计），合计132.17秒；包含启动器的服务墙钟合计133.98秒。更早S1AA的软件阶段服务墙钟为25.23秒，S1Z-D为124.93秒。这些数字来自各阶段SESSION_RECEIPT，不包含完整对话中的实现、阅读、推理、工具交互和交接整理时间。

1500秒/1800秒等是事前设置的实验服务预算上限，并非实际耗时，也不要求一到这个规模就结束项目工作。当前记录没有分别计量开发和交接时间，不能给出这些部分的精确占比。

此前存在两个组织问题：短包的冻结、脚本编排和交接工作重复较多；小实验完成后，往往把封存点当成用户交接停点，造成用户反复说“继续”。此外，在A局部控制上消耗了较多迭代，却尚未得到合格数据。后续保留实验可追溯和有限预算，减少重复基础设施与短包之间的人为停顿。

## 8–12周滚动规划基线

以下周数是工程粗排期，用于组织依赖和复查投入，不是已经验证的工期承诺，也不是连续后台运行的安排。控制方案能否完成任务是主要不确定项；时间到达不代表自动取得下一阶段资格。达到退出条件时切换路线，不靠延长同例调参凑进度。

|里程碑|粗排期|必须交付|验收与未通过后的去向|
|---|---|---|---|
|M1 可采集参考方案准入|第1–2周|B完整策略历史恢复、原生手非零动作消费；同时梳理已有成熟全身控制/专家采集接口，给A/B各自能力与缺口结论；得到至少一条完整任务的可执行候选入口|站立/动手只算子项。候选需在限定用途内展示完整取放路径，失败记录可定位。B有限准入失败则收束，不复制A的多轮局部调参；不存在可执行候选时汇报路线阻塞与具体替代，而不启动大批采集|
|M2 自有场景中的可重复完整任务|第2–4周|固定本体、控制器、场景、对象、初态、动作和任务判据；自动接近、抓取、试提、搬运、释放、撤回、落稳；失败可自动停止和分类|新合格方案的开发稳定性暂定固定20次评测、至少18次全任务通过；真实身体稳定和物理门仍须逐条满足。这个小样本门不证明泛化；评测前冻结分母和条件，不凑成功次数，不重开已关闭的Stretch两例第4次|
|M3 实际采集与标准导出闭合|第3–5周，基础工程可与M2交错|真实相机/本体观测、实际动作、时间戳、任务状态、失败标签；统一记录/质检/导出/重载接口；小批轨迹经真正训练读取器读通|核验像素与归一化统计、相机内容、动作名称/单位、t到t+1对应、导出重载一致性；特权专家字段与学习输入隔离。失败轨迹可提前用于接口开发，只有M2合格轨迹才获得相应任务数据资格|
|M4 多物体与有限空间试点|第5–7周|事前固定开发矩阵，例如6种刚体×3种空间配置、每组合10次，共180次尝试；另留未参与调参的物体/布局作独立评测；运行自动采集和质检|按组合报告成功率、拒绝率、合格产量、人工介入、时间/存储成本和实际多样性。失败不能替换掉分母；已有杯/瓶/书本及其衍生调试记录不能伪装为未见验证材料|
|M5 下游学习价值验证|第7–9周|先得到冻结训练/评测条件下可重复的学习基线，再比较等样本量、等训练预算的低/高多样性数据；采用成熟学习组件，不为每个场景单独从零训练|实际部署可用观测上的任务成功与泛化结果、重复种子和不确定性；先验收真实学习输入，再训练。0对0、loss下降、专家成功或画面改善都不证明数据有效；无收益时先做有界问题归因，不直接扩量|
|M6 批量生产试运行|第9–12周|任务队列、资源管理、失败恢复、版本血缘、去重、抽检、指标看板；事前固定较大规模试运行分母和成本上限|基于M4/M5的合格率与学习证据制定生产门。报告每条合格轨迹成本、每小时产量、人工时间、分布覆盖和质量漂移；不能只以总生成条数作为完成标准|

M2、M4的数值是本路线的暂定工程验收设计，实际运行前需结合选定方案和资源冻结，不是外部标准或已有能力。已封存阶段的严格门和退出条件不因这些新目标而放宽。M6的具体条数、硬件和GPU预算待单位成本已知后制定，本次文档更新不启动任何实验。

## 三条工作线及依赖

1. 机器人任务线：控制状态恢复、原生命名动作、全身稳定、规划和完整取放。优先复用成熟能力。A当前控制搜索已结束；B的后继不是无限站立/动手测试，而是尽快进入完整自有场景任务准入。
2. 数据工程线：从现有保存记录提炼通用日志、失败分类、时间/动作契约和导出入口。基础接口可以在控制方案尚未完全成熟时推进，质量标签必须保持真实；A/B保留各自本体动作语义，不用补零伪装同构。
3. 质量与学习线：先冻结开发/验证隔离、字段来源、图像/动作输入检查与评测器，等任务和学习输入基线满足后进入训练。避免到训练失败才检查数据恒定、单位或时间对齐。

这三条线描述依赖关系，不意味着启动额外代理、无限并行作业或未声明资源。实际任务仍在当前授权和资源约束内组织。

## 接下来第一个连续工作包

具体B前置沿用[S1AB之后的有限计划](/data/wsj/main/scene_runs/codex_trellis_v2/embodied_grasp_final_trial_20260925_v1/NEXT_STEP.md)：完整积分状态及6帧历史/previous-action恢复 → 具名动作与零目标等价检查 → 固定非零手路径静态检查 → 条件唯一4秒800步动态 → 保存审计。

该B子包仍最多3服务/1200累计秒、1次新动态、至多202次新前向，不重跑旧站立，不清零原始基座漂移参考，不改旧门。前置或动态失败按原退出条件停该子包。

随后按结果继续：

- B准入通过：接自有场景站位、上肢可达性和全手接触条件，事前声明有限候选/动态预算；同步复用已做的数据记录和任务门。完成一项手部小测试不自动视为M1完成。
- B准入失败：关闭该子问题的追加尝试，转已有成熟控制/采集接口的证据盘点，最多形成两个有明确实际任务入口的候选。候选必须符合全身移动参考本体用途；固定基座、隐形支撑或录像展示不能替代资格。没有可用候选就报告具体缺口，不换对象继续试到成功。
- 无论B哪种结果：可继续做不依赖新增物理资格的通用记录、失败分类与真实读取器准备。保持这些工程成果与任务/学习资格分列。

新阶段预算约束新的不同问题，不重置旧组合累计次数，不用更名绕过停止条件。新增路线在执行前仍需有明确输入、预期响应、有限预算与退出条件；这属于执行准备，不意味着所有普通步骤都要向用户重新请求许可。

## 后续协作与汇报方式

- 用M1–M6里程碑管理工作，短实验包作为内部可恢复检查点；一个包结束后，若后继已明确、已有授权且满足前置，就继续推进。
- 持续工作中仍提供简短进度，重点报告新证据、当前判断和下一项验证；不把普通文件写完或一次工具返回都当作重要节点。
- 阶段结论、路线变化、资源将实质超出既定范围、需要用户提供不可推断的信息时集中汇报；已有方向和同类授权不重复询问。
- 用户提问或修改约束时及时回应。解释状态、封存可恢复断点不等于虚构后台持续运行。
- 通用启动器、manifest、源码版本绑定和报告模板逐步复用；不要为每个小阶段复制一套大段编排和说明。检查强度匹配实际改动，已通过且未改动的测试不重复运行。
- 后续开始记录连续工作包开始/结束、各计算服务耗时、可识别等待和人工介入事件。不能可靠测出的开发/推理耗时标为未单独计量，不用服务CPU时间冒充全部项目成本。

## 长期质量看板与每次路线复查

固定看七类指标：完整任务成功/首次失败；有效物体与空间覆盖；工程合格轨迹数；全部尝试和被拒分母；每条合格轨迹的时间/存储成本；人工介入；冻结评测上的学习效果。另保留物理建模先验和几何保真范围，避免把仿真稳定解释为真实硬件可信。

每个里程碑结束时核对：新增的可复用能力是什么、距离可用训练数据还缺什么、继续当前路线是否比复用成熟方案更有价值。局部失败应该产生可复用回归和路线判断，而非永久阻塞全项目。

## 首个数据闭环之后

在完整任务和学习价值有证据后，再扩展到邻近不同支撑面、更多任务、移动底盘参与和导航—操作协同，并为自研本体建立观测/动作适配、参数范围和验证矩阵。硬件设计、制造、传感器与真实物性标定另列依赖与预算；参考平台上的结果不自动授予自研硬件的部署资格。

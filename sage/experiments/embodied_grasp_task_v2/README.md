# 完整取放执行包装 v2

复用已冻结的 closure_v2 控制器和 NativeTaskConsumer，补齐各阶段完整步数、真实试提采样窗口、释放从最后实际指令开始、释放完成后撤回及落稳。此包装直接进入新的完整执行器；不改旧源码、模型、物性、动作路径和门。

`CompleteTaskConsumer.consume` 原子校验原生命名动作，再发送。闭合到放置调用原v2消费者；完整test_hold结束时消费其真实0.5s预步进采样窗口，同时执行器保留旧0.5s后步进窗口门、全身稳定、接触角色、物体倾角等门。任一拒绝立即停止该例后续阶段。

`begin_release` 必须在place完成、试提通过和最后place准备条件满足后调用，初始grip严格取上一实际ctrl。之后沿原2秒五次平滑释放曲线、3秒撤回及2秒落稳曲线，校验真实上一指令、1ms时序、完整阶段步数和原生范围。开夹阶段不再要求夹持承载；仍受旧全身/物体/最终释放验收。

preflight模块分开记录真实保存状态消费、软件历史预置下真实接触/支撑采样、明确合成观测的完整试提正窗口与拒绝，以及完整时长的释放/撤回参考消费。全部0积分，合成输入不构成任务成功。真实闭环由execution模块单次运行，审计仅消费保存数据，不重放物理。

本轮每开发组合最多第3次，失败没有新试跑槽。通过完整取放也仍需实际观测与标准导出、独立评测和学习基线；不能据此称批量数据或学习有效。

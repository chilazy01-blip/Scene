# Development production pilot

This separate module and its frozen run turn the existing generated-book/container task into a bounded three-configuration batch. The run is `/data/wsj/main/scene_runs/codex_trellis_v2/embodied_production_pilot_20260921_v1`.

`adapter.py` preserves the frozen container adapter except that every input can use the existing ten-candidate mount search, including the two target-relative candidates. `accounting.py` distinguishes registered source slots, executed attempts, physical success, replay, image acceptance and official export; a raw success flag cannot qualify a training episode.

The actual requests use the public scene generator and preserve assembled geometry. The supported container profile remains specific to the existing historical basket; every new GLB gets its own measured surface-voxel and cavity binding. All configurations belong to the same development asset-source group and study layout family.

The machine protocol, immutable attempt directories, entrypoints, standard dataset shard index, complete rejection ledger, costs and final audit live in the run. Use its `tools/launch_v3.py` and `tools/orchestrator.py` only according to that frozen protocol; never rerun completed attempts. Heavy stages require the original P007 admission, eight-CPU affinity, 12/16GiB memory, 900-second service limit and shared GPU lease/watchdog for rendering.

No new learner, dependency installation, held-out dataset or real-world data-value claim is part of this pilot. A batch can finish with a failed release gate; reports must retain that distinction.

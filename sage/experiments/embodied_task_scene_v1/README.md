# 完整任务场景交接 v1

解决生成类别与实例ID错配、重复目标，以及任务目标姿态只存在于隔离模型的问题。当前交付完整场景的起点/目标消费入口和有限Panda预检，不提供已通过的机器人控制或训练数据生产能力。

`semantic.prepare` 调用既有任务选择和原规则解析器，解析真实实例ID；`validate_roles` 在生成前后检查数量、唯一身份、源资产和支撑边。类别名不能替代实例ID。

`package.build` 消费实际公共生成GLB，保留所有家具、门窗及墙地面。源场景作为起点，只对目标实例施加明确的刚体变换，写出 `scene_goal.glb`；GLB几何/纹理二进制不变。任务同时声明 `start_pose_z_up` 和 `goal_pose_z_up`，仿真视觉与碰撞共享目标刚体姿态。原文件及历史失败不覆盖。

支撑接触使用既有5mm源上下界柱，区域外用10mm无膨胀源表面体素；其他物体使用源凸包的保守近似。质量、惯性和摩擦为原显式先验，未标定。目标姿态变化不代表全场景物理真值已验证。

`verify.verify` 独立读取起点/目标GLB、OBJ和原生模型，核对语义实例、逐顶点姿态、非目标保留、质量惯性和相对资产路径。`render_diagnostics` 验证CPU软件相机、浮点RGB统计与PNG往返；画面数值正常不代表能观察任务，须另检查可见性。

`robot.preflight` 在固定8个安装位、1个抓持关系上，分别求抓取、抬升、转平、释放和退出姿态；关节插值按固定步长检查当前完整碰撞模型。持物位姿预测仅用于零积分检查，不能冒充真实抓持或动态成功。当前8个候选全部拒绝：4个转平IK位置误差超限，4个下降释放插值发生桌面碰撞。未启动动力学，未追加搜索。

实际入口：

```bash
python -m sage.experiments.embodied_task_scene_v1 \
  --entry /absolute/config/ENTRY.json --sha256 EXTERNAL_PIN \
  --request-id D02R1 --state goal --purpose scene_inspection
```

`--state start` 加载直立起点，`goal` 加载平放目标；均重新核验绑定文件和场景姿态再返回原生模型。机器人执行、合格采集和导出用途拒绝。没有从其他隔离模型继承动态资格。

原生XML及相对资产文件可迁移，已用独立进程验证两个状态。入口记录的绝对证据引用没有自动迁移；迁移证据须重新显式绑定，不能声称把目录搬走就获得同一资格。

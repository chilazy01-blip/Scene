# 条件化仿真能力检验

用户于 2026-09-26 批准执行能力参数化、完整任务基线、留出验证、学习对照路线。本模块服务该路线；此前严格 SG3 硬件来源准入的失败记录仍有效。

`runtime.py` 从钉住的 Stretch MuJoCo 源模型派生独立场景，保持自由底盘、自由物体、原生伺服增益和命令范围。未知努力上限和有效轮阻力在外部协议事前声明为 assumed；原轮阻力 35 N·m 写入来源信息。内部重力前馈消耗相同执行器出力预算，所有执行器有限限幅。没有外部托举、位置重置步进或隐形支撑。

模型原本的夹爪接触、弹性约束和摩擦仍是仿真假设。软件运行或任务成功都不构成真实 SG3 标定。新模块没有把 assumed 参数伪装成旧 `AffineServo` 的 qualified 硬件来源登记。

`checker.py` 按模型、控制器、任务和条件绑定的身份精确查询实测记录。输出尝试分母、成败、未完成、失败原因和描述性 Wilson 区间；未知条件、真机请求返回 unknown。拒绝重复身份和无保存审计支持的成功。空载能力与完整任务结果分开，不能用移动成功代替取放成功。

运行协议和完整记录：`scene_runs/codex_trellis_v2/embodied_stretch_ai_admission_20260926_v1/capability/`。新运行必须经过同根 `tools/launch_capability.py` 及实际累计预算。此前关闭的 A/G1 配置不能通过此模块重跑。执行状态以运行目录 RESULT、COUNTERS 和服务终态为准。

`scene.py` 将已有自有生成书房完整接入原生机器人；源书本保持自由刚体并检查非任务扰动。原生碰撞形状、求解器和控制增益不变。检查器在椭圆摩擦锥条件下读取真实接触约束力，并经过保存状态与原生接口逐值对照。未使用的雷达/IMU输出计算可以在有等价性证据时关闭，数据不声明含这些模态。

`dataset.py` 从500Hz实际轨迹导出100Hz关节观测、上次参考、实际参考命令、内部前馈后的控制量及下一状态，逐值逐类型通过真实PyTorch DataLoader。完整自由物体和底盘状态另存privileged组。相机是独立的稀疏保存状态重建，不能伪装成每条轨迹的全速视觉数据。

`lerobot.py` 复用已钉住的LeRobot/GR00T写入与Typed读取器导出同一批轨迹，保留失败episode和discarded标签。该桥接只描述条件仿真研究数据，不能把格式兼容解释为硬件或批量生产资格。

`learning.py` 是有限的状态模仿诊断：固定时间基函数、关节状态及明确的初始物体坐标。训练行数与模型相同，先验证学习器闭环正例，再运行冻结的成对场景/初态条件。没有视觉学习、实时物体真值输入或专家动作接管；训练误差和专家成功均不能代替学习器的完整取放结果。

`tracking.py` 是在原始速度复制型学习基线失败后、事前另行冻结的动作接口验证：从相同示范学习10维参考命令和2维轮编码器轨迹，取消即时速度回归输入，以固定的1/s、2/s编码器反馈跟踪。旧学习模型与失败不覆盖。小型成对测试的2/6与5/6只适用于给定场景与初态、带显式初始几何和时钟的状态策略；确认性复验另外冻结新初态和模型哈希，不用评测数据重新训练。

`support_task.py` 从自有包的支撑几何计算任务位置，并实现采样支撑多边形检查。视觉包围盒顶高不能代替真实碰撞表面；刚体可由部分高接触点支撑，静态COM位于支撑多边形内也不保证整个机器人任务无碰撞。矮桌实例通过采样支撑预检后，第2次取放在释放时触发原15N非预期接触门，此固定配置已关闭，没有重试或降低门槛。

完整任务数据的分割必须保持：45参考开发+20书房开发可以用于这次训练；29成功留出、3成功基线、后续确认性初态均单独保留。两套学习接口各6模型的实际来源哈希均可审计。失败记录不删，未经场景准入的个别成功不能变成该场景的稳定采集资格。

查询工具：运行目录 `tools/query_capability.py` 列出可查询的确切条件；`--condition HASH --kind KIND` 返回实际尝试、成败、区间及失败原因。未测条件与真机请求返回unknown；查询结果不作能力外推或“机器人不可能完成”的断言。

multimodal.py提供完整10Hz双相机RGB-D与100Hz动作块的读取接口，每个图像时刻对应后续10条真实动作。公开输入包含关节/速度/上次参考、相机像素、理想米制深度及有效掩码、原生仿真内参和光学系到机器人基座的FK外参；分割和世界坐标只用于质检。稀疏profile不能以完整训练episode目的读取。全长重建不重新积分、不补造动作。

multimodal_lerobot.py调用钉住的官方LeRobot写入器，以PNG无损图像和动作块导出。实际Typed读取器应逐像素核验float32 CHW/255图像及原始uint8可恢复性，所有数值字段逐值逐类型验证。原生格式中action的100维按行优先还原成(10,10)（10个100Hz时刻×10执行器），observation.state是10位置+10速度+10上次参考；语义和单位保存在meta/scene_source.json。精确float32深度和bool有效掩码保留在原HDF5、经相对路径和哈希绑定，不能声称它们是原生Parquet中的视频字段。所有验收结果读运行根capability_multimodal/RESULT.json及服务证据，代码存在不等于全量审计已通过。

`perception.py` 提供固定蓝色像素规则、真实深度/FK投影和9维点云统计的中心估计诊断。V在12开发序列训练后冻结权重，24独立确认条件的初态仅12/24通过1cm门（书房12/12、参考0/12）；删除错误前景也未改善参考失败。该固定基线已关闭，不用于视觉闭环，不在这24例上继续调参。几何/可见面覆盖不足是待分离因素，不能只凭该诊断断言单因果。

后继 `capability_geometry_collection` 在运行根中准备两种新生成布局、7种固定盒尺寸、48个固定初态；48/48无积分预检通过。40开发/8独立验证、串行队列、失败退出与数据审计入口已准备，尚未新增动态。布局复用同一桌面位置和原资产，不能宣称独立房型/新资产泛化。完整RGB-D只从成功开发轨迹生成，验证稀疏图不进入训练；单腕部相机的实际官方写入与深度消费已通过270行既有数据回归，该回归不计新增采集产量。
